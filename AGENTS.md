# ndw-iot-firmware

NDW's open-source meter firmware and the manifest the flasher reads. A public repository: a branch and a pull request, as the global rule says. Baseline: `~/.claude/CLAUDE.md` (global); this file adds what is particular to the firmware. What the firmware and its release pipeline do lives in `openspec/specs/` and `openspec/changes/`; this file holds the rules for working here.

## Layout
- `src/core/` platform-free C++ (LoRaWAN stack, meters, fleet, station, interfaces); `src/hal/` ESP32; `src/radio/` LoRa (SX1262) and BLE (NimBLE); `src/boards/<vendor>/<variant>` the PlatformIO builds; `src/host-tests/` the core on the host.
- `builds/` committed binaries and `build.json` per board; `manifest.json` generated by `scripts/build-manifest.py`.
- `README.md` is the orientation; `HANDOFF.md` is the session handoff only.

## Build and test
- Host tests: `cd src/host-tests && pio test -e native`. CI runs them before any board is built.
- Boards: `pio run` in the board's folder. No Docker on the Mac for our work: the C3 toolchain is Intel-only on Apple silicon, so build it on gpu1 or a Linux host (or install Rosetta).
- Flash with esptool; writing only `0x10000 app.bin` keeps a board's NVS (fleet, Wi-Fi, token).

## OpenSpec
- Behavior changes start as an OpenSpec change (`openspec/changes/`), built and verified with the skills in `.agents/skills/`, then archived so requirements land in `openspec/specs/`.
- Validate with `npx -y @fission-ai/openspec@^2 validate --all --strict`. Follow `openspec/config.yaml` (scenario and proof-note format).

## Releases
- CI publishes each board by committing its binaries, `build.json` and `manifest.json` straight to `main`, one commit per board, in parallel jobs. After a push, `main` moves on by several commits: `git pull --rebase` before the next push, and where `builds/**` or `manifest.json` conflict, regenerate with `python3 scripts/build-manifest.py`. The flasher and iot.ndw.ai read `manifest.json` from `main`.
- Bump the board's `build.json` revision on every change, so each version is unique.

## BLE (NimBLE)
- Never `NimBLEScan::stop()` and `start(…, false)` around an uplink: both clear the results from the app task while NimBLE's host task may be delivering one, and the fleet hung within minutes. Cancel with `ble_gap_disc_cancel()` and resume with `start(0, nullptr, true)`.
- On the C3's one radio, scanning while advertising starves the board's own advertisements.
